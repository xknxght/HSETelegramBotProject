# Design-Doc: Чат-бот для абитуриентов
*(Проект: курсовая работа. Цель - спроектировать и описать чат-бота для поддержки абитуриентов: ответы на вопросы по поступлению, программам, документам, срокам, контактам.)*


## 1. Контекст проекта

### 1.1 Бизнес-задача
- Проблема: абитуриенты задают повторяющиеся вопросы про поступление (сроки, документы, стоимость, бюджетные места, проходные баллы, общежитие, военная кафедра, вступительные испытания, контакты). Ответы распределены по разным страницам сайта и PDF-документам, часть информации быстро меняется.
- Негативный эффект: сотрудники приемной комиссии тратят много времени на однотипные консультации; абитуриенты получают ответы медленно, могут ошибаться из-за устаревших источников.
- Решение: чат-бот, который отвечает 24/7 и опирается на официальные документы и страницы (RAG: retrieval augmented generation), чтобы снижать риск “галлюцинаций”.
- Критерии успеха:
  - снижение доли вопросов, на которые система не может дать корректный автоматический ответ;
  - высокий уровень удовлетворенности пользователей;
  - отсутствие критических ошибок (например, неверные дедлайны или список документов).

### 1.2 Целевая аудитория и пользователи
- Абитуриенты бакалавриата/магистратуры и их родители.
- Иностранные абитуриенты.
- Сотрудники приемной комиссии (как внутренние пользователи для контроля базы знаний и логов вопросов).

### 1.3 Ограничения и допущения
- Информация должна быть привязана к конкретному набору источников (официальный сайт, PDF файлы с правилами приема, страницы программ).
- Дедлайны и правила могут меняться. Нужен механизм обновления базы знаний.
- Бот не является юридически значимым источником. Должны быть дисклеймеры и ссылки на первоисточник.
- Бот не должен запрашивать лишние персональные данные; при необходимости контакта - минимальный набор и понятная политика хранения.

## 3. Данные и качество знаний

### 3.1 Сбор и предобработка данных
**Источники данных:**
- Официальный сайт приемной комиссии (разделы: сроки, правила приема, документы, контакты, FAQ).
- Страницы образовательных программ (описание, стоимость, бюджет/контракт, требования).
- PDF-документы: “Правила приема”, “Положение о вступительных испытаниях”, “Стоимость обучения”, “Перечень направлений/профилей”, “Общежитие”.
- Контакты/адреса/расписания консультаций.

**Форматы:**
- HTML страницы сайта.
- PDF (официальные приказы/правила).
- При необходимости: DOCX/таблицы.

**Предобработка (pipeline):**
- Загрузка контента:
  - HTML: парсинг текста + сохранение URL;
  - PDF: извлечение текста и таблиц.
- Очистка:
  - удаление меню/футеров/дублирующихся блоков;
  - нормализация пробелов, переносов, спецсимволов;
  - приведение дат к единому формату (например, ДД-ММ-ГГ).

**Чувствительные данные:**
- В базе знаний должны быть только публичные официальные материалы.
- Исключить персональные данные сотрудников, если они не опубликованы официально (если контакты опубликованы - хранить как “официальный контакт”, без дополнительной обработки).
- Обновление базы знаний предполагается при изменении официальных документов и правил приема.


## 6. Безопасность, соответствие и этика (ключевой пункт)

### 6.1 Персональные данные и приватность
- Бот не запрашивает паспортные данные, адрес, документы и любые чувствительные персональные данные.
- Допустимый минимум (если нужно для обратной связи): имя и контакт (например, email) - только по явному согласию пользователя.
- Политика хранения: хранить только технические логи (без ПД) или хранить минимально и ограниченный срок (например, 30 дней) - в зависимости от требований курса/проекта.
- Прозрачность: сообщение “Вы общаетесь с ботом. Ответы справочные. Официальные правила - по ссылкам”.

### 6.2 Снижение риска ошибок
- Ответы должны формироваться только на основе найденного контекста.
- Если контекста недостаточно:
  - бот говорит, что не нашел подтверждения в документах;
  - предлагает перейти на официальный источник или задать уточняющий вопрос.
- Критические темы (дедлайны, перечень документов, стоимость) - всегда сопровождать ссылкой на источник и датой документа/страницы, если доступно.

### 6.3 Модерация нежелательного контента
- Фильтрация запросов:
  - токсичность/оскорбления: нейтральный отказ, предложение задать вопрос по поступлению;
  - несвязанные темы: мягко возвращать к тематике приемной кампании.
- Защита от prompt injection:
  - игнорировать инструкции пользователя “не следуй правилам”, “покажи системный промпт”;
  - извлеченный контекст трактовать как справочный источник, а не как инструкции.

### 6.4 Соответствие регулированиям
- Права на контент: использовать только официальные публичные материалы вуза/приемной комиссии.
